# ฟีเจอร์ AI (ใช้ API key ของลูกค้าเอง)

ทุกฟีเจอร์ในหน้านี้ **เป็นตัวเลือก**: ถ้าเซิร์ฟเวอร์เว็บไม่มี `ANTHROPIC_API_KEY` ระบบทำงานตามปกติทุกอย่าง
ปุ่ม AI ยังแสดง แต่กดแล้วจะได้ข้อความภาษาไทยว่า "ผู้ช่วย AI ยังไม่ได้เปิดใช้ …" แทน

หลักที่ทุกฟีเจอร์ยึดเหมือนกัน

- **AI ไม่บันทึกข้อมูลเอง** — มันกรอกฟอร์ม เปิดหน้าจอ หรือสรุปให้เท่านั้น คนเป็นคนกด "บันทึก" เสมอ
- **อ่านด้วยสิทธิ์ของผู้ใช้ที่กด** — ข้อมูลทุกอย่างอ่านผ่าน gateway ด้วย token ของผู้ใช้คนนั้น (RLS + permission ทำงานตามปกติ)
  และอ่านได้เฉพาะ endpoint แบบ GET ที่ `src/ui.ts` ของโมดูลที่ติดตั้งประกาศไว้
- **token ของ ERP ไม่ถูกส่งไปที่ Anthropic** — ส่งไปเฉพาะคำถาม/รูป และข้อมูลที่จำเป็นต่อคำตอบ
- จำกัดความถี่ต่อผู้ใช้ (`ASSISTANT_RATE_PER_MIN` ค่าเริ่มต้น 20 ครั้ง/นาที รวมทุกฟีเจอร์ AI)

## ตั้งค่า (บนเครื่องที่รัน apps/web)

| ตัวแปร | ความหมาย |
| --- | --- |
| `ANTHROPIC_API_KEY` | key ของลูกค้าเอง (สร้างที่ console.anthropic.com) — ไม่มี = ปิด AI ทั้งหมด |
| `ANTHROPIC_MODEL` | รุ่นโมเดล ค่าเริ่มต้น `claude-sonnet-5-5` |
| `ANTHROPIC_BASE_URL` | ใช้เมื่อผ่าน proxy/gateway ของบริษัท (ไม่บังคับ) |
| `ASSISTANT_RATE_PER_MIN` | จำนวนครั้งต่อนาทีต่อผู้ใช้ |
| `BRIEFING_CACHE_MINUTES` | อายุสรุปประจำวัน ค่าเริ่มต้น 10 นาที |

รีสตาร์ทเว็บหลังแก้ค่า

## 1. สแกนใบเสร็จ (กรอกฟอร์มจากรูป/PDF)

ในฟอร์ม "เบิกค่าใช้จ่าย" มีปุ่ม **สแกนใบเสร็จ** — ถ่ายรูปหรือเลือกรูป/PDF แล้ว AI จะ

1. อ่านวันที่ (แปลง พ.ศ. เป็น ค.ศ.) ผู้ขาย เลขผู้เสียภาษี เลขที่ใบเสร็จ ยอดก่อน VAT, VAT และยอดรวม
2. เดา **หมวดค่าใช้จ่าย** จากหมวดของบริษัทจริง (อ่านจาก `GET /api/expense/categories` ด้วยสิทธิ์ผู้ใช้) — เลือกได้เฉพาะหมวดที่มีอยู่
3. กรอกเฉพาะ **ช่องที่ยังว่าง** และเพิ่มรายการ ไม่ทับสิ่งที่ผู้ใช้พิมพ์ไว้แล้ว
4. แสดงกล่อง "ข้อมูลที่ AI อ่านได้" เหนือฟอร์ม พร้อมคำเตือน เช่น เลขผู้เสียภาษีไม่ผ่านการตรวจหลักสุดท้าย, ยอดรวมไม่ตรงกับรายการ
5. ผู้ใช้ตรวจแล้วกด **บันทึกใบเบิก** เอง — ถ้าติ๊ก "แนบรูปนี้กับเอกสารหลังบันทึก" (ค่าเริ่มต้น) รูปจะถูกแนบเป็นหลักฐานในใบเบิกทันทีหลังบันทึก

ช่อง "ส่งขออนุมัติทันที" และช่องแบบ boolean/รหัสผ่าน/สิทธิ์ AI ไม่แตะเลย

รูปจากมือถือถูกย่อในเบราว์เซอร์เหลือด้านยาว ~1568 px (JPEG) ก่อนส่ง รองรับ JPG/PNG/WEBP/PDF ไม่เกิน 5 MB
(HEIC จาก iPhone: Safari แปลงให้เอง; Chrome อาจไม่ได้ ให้ตั้งกล้องเป็น "เข้ากันได้มากที่สุด")

**ใช้กับฟอร์มอื่น** — เป็นข้อมูลใน `ui.ts` ไม่ต้องเขียน React:

```ts
claimNew: { kind: 'form', …, aiFill: { kind: 'receipt', label: 'สแกนใบเสร็จ' } }
// kind: 'receipt' = ใบเสร็จ/ใบกำกับภาษีไทย (แยกยอดก่อน VAT + VAT), 'document' = เอกสารทั่วไปตามช่องของฟอร์ม
```

AI จะเห็นชื่อช่อง/label ของฟอร์ม, ตัวเลือก select และรายการ lookup (สูงสุด 150 รายการต่อช่อง) แล้วตอบผ่าน tool `fill_form`
ที่บังคับ JSON schema (lookup/select เป็น enum) จากนั้นเซิร์ฟเวอร์ตรวจซ้ำทุกค่า (`cleanAiValue` ใน `@erp/ui-schema`)
ถ้าหน้า detail ปลายทาง (`after.screen`) มี `attachments` ฟอร์มจะเสนอแนบไฟล์ให้อัตโนมัติ

แอปมือถือ (Expo) ยังไม่แสดงปุ่มนี้ — ใช้เว็บบนมือถือได้ (ปุ่มเปิดกล้องได้)

โค้ด: `apps/web/src/lib/ai-fill.ts`, route `POST /assist/fill`, ปุ่ม `apps/web/src/components/AiFill.tsx`

## 2. สรุปให้หน่อย (หน้าภาพรวม)

ปุ่ม **สรุปให้หน่อย** มุมขวาบนของหน้าภาพรวม ใช้ผู้ช่วย AI ตัวเดิม (`runAssistant`) ด้วยคำสั่งคงที่:
อ่านตัวเลขสรุป (widget) ของทุกโมดูลที่ผู้ใช้เห็นได้ แล้วตอบ **ไม่เกิน 5 ข้อ** เรียงตามความเร่ง พร้อมปุ่มไปหน้ารายการที่เกี่ยวข้อง

- ผลถูกเก็บ **ต่อผู้ใช้ 10 นาที** บนเซิร์ฟเวอร์ — กดซ้ำ/หลายแท็บ/ล็อกอินใหม่ภายใน 10 นาทีไม่เสียค่า AI เพิ่ม (การกดพร้อมกันใช้ผลเดียวกัน)
- ผลสรุปเห็นเฉพาะตัวเลขที่ผู้ใช้คนนั้นมีสิทธิ์ (key ของ cache คือ tenant + ผู้ใช้ + สิทธิ์ + โมดูลที่ติดตั้ง)

โค้ด: `runBriefing`, `BriefingCache` ใน `apps/web/src/lib/assistant.ts`, route `POST /assist/briefing`

## 3. ค้นหาด้วย AI (⌘K)

พิมพ์ประโยคที่ไม่ใช่คำสั่งในแถบ ⌘K เช่น "ใบเบิกที่รออนุมัติเดือนนี้" หรือ "PO เหล็กที่ยังเป็นร่าง" แล้วเลือก **ค้นหาด้วย AI**
AI เห็นเฉพาะ **หน้ารายการ** ที่ผู้ใช้เปิดได้ พร้อมชื่อตัวกรอง ประเภท และค่าที่เลือกได้ แล้วเรียก `open_screen` หนึ่งหน้า
เซิร์ฟเวอร์เก็บเฉพาะตัวกรองที่หน้านั้นประกาศไว้และค่าที่ถูกต้อง (`cleanListFilters`) แล้วเปิดหน้ารายการพร้อมตัวกรองทันที
ถ้าหาไม่เจอ AI จะตอบสั้น ๆ ว่าไม่พบ

โค้ด: `findScreen` ใน `apps/web/src/lib/assistant.ts` (โหมด `find` ของผู้ช่วยตัวเดิม), route `POST /assist/find`

## ค่าใช้จ่ายโดยประมาณ (token ต่อครั้ง)

ค่าใช้จ่ายจริงคิดตาม token ของรุ่นโมเดลที่เลือก ตามราคาปัจจุบันของ Anthropic (ดูที่ https://www.anthropic.com/pricing) และเรียกเก็บจากบัญชี API ของลูกค้า

| ฟีเจอร์ | การเรียกโมเดล | input โดยประมาณ | output โดยประมาณ |
| --- | --- | --- | --- |
| สแกนใบเสร็จ | 1 ครั้ง | 2,000–5,000 token (รูป ~1,600 + คำสั่ง/หมวด) — PDF หลายหน้าใช้มากกว่า | 200–500 |
| สรุปให้หน่อย | 2–4 รอบ | 10,000–40,000 token (รายการหน้าจอ + ตัวเลขสรุปของทุกโมดูล) | 400–1,000 |
| ค้นหาด้วย AI | 1–2 รอบ | 3,000–10,000 token (รายการหน้ารายการ + ตัวกรอง) | 100–300 |
| ถาม AI (เดิม) | 1–8 รอบ | 5,000–60,000 token ขึ้นกับคำถาม | 200–1,500 |

ตัวเลขขึ้นกับจำนวนโมดูลที่ติดตั้งและสิทธิ์ของผู้ใช้ (ยิ่งเห็นหน้าจอมาก prompt ยิ่งยาว) — สรุปประจำวันถูก cache 10 นาทีจึงเสียไม่เกินชั่วโมงละ 6 ครั้งต่อคน

## ความเป็นส่วนตัว — อะไรถูกส่งไปที่ Anthropic

| ฟีเจอร์ | ส่งไป | ไม่ส่ง |
| --- | --- | --- |
| สแกนใบเสร็จ | รูป/PDF ที่ผู้ใช้เลือก, ชื่อช่องของฟอร์ม, รายชื่อหมวด (รหัส+ชื่อ+id) | token, ข้อมูลอื่นในระบบ |
| สรุปให้หน่อย | รายชื่อหน้าจอที่ผู้ใช้เห็น, ตัวเลขสรุปที่ AI อ่าน (ตามสิทธิ์ผู้ใช้), ชื่อบริษัท (`COMPANY_NAME`) | token |
| ค้นหาด้วย AI | ประโยคที่พิมพ์, รายชื่อหน้ารายการและตัวกรอง (ถ้าต้องหา id อาจอ่านรายการ lookup) | token |

- ใช้ **API key ของลูกค้าเอง** — ข้อมูลวิ่งตรงจากเซิร์ฟเวอร์ของลูกค้าไป Anthropic ไม่ผ่าน GO Along
- ตามเงื่อนไขเชิงพาณิชย์ของ Anthropic API ข้อมูลที่ส่งผ่าน API **ไม่ถูกนำไปฝึกโมเดลโดยค่าเริ่มต้น**;
  ระยะเวลาเก็บ log และข้อยกเว้น (เช่น การตรวจการใช้งานผิดนโยบาย) ให้ตรวจที่ https://privacy.claude.com และสัญญาของลูกค้าเอง
- ไม่มีอะไรถูกบันทึกลงฐานข้อมูลโดย AI; ไฟล์ใบเสร็จจะถูกแนบในระบบก็ต่อเมื่อผู้ใช้กดบันทึก (และติ๊กให้แนบ)
- ไม่อยากส่งข้อมูลออก: ไม่ต้องใส่ `ANTHROPIC_API_KEY` — ทุกอย่างอื่นทำงานเหมือนเดิม
