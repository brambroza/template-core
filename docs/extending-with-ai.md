# ต่อยอดระบบด้วย AI (สำหรับทีมลูกค้า)

ระบบนี้ไม่ได้แข่งกับ AI — เราขาย **ฐานที่ถูกต้อง** (ภาษีไทย, สิทธิ์, แยกข้อมูลแต่ละบริษัท, event ระหว่างโมดูล, test เกือบพันข้อ)
แล้วให้ AI coding tool ของคุณ (Claude Code, Cursor, Codex ฯลฯ) **ต่อยอดบนฐานนั้น** ได้เองตามงานของบริษัท

หัวใจคือแบ่งโค้ดเป็น 2 ส่วนชัดเจน:

| | โค้ดหลัก (vendor) | ส่วนต่อยอดของคุณ |
|---|---|---|
| อยู่ที่ | `packages/`, `apps/`, `services/<โมดูล>/src`, `migrations`, `test` | `services/<โมดูล>/ext/` และโมดูลที่คุณสร้างเอง |
| ใครแก้ | GO Along (ส่งเป็นรุ่นอัปเดต) | ทีมคุณ + AI |
| อัปเดตจาก GO Along | ถูกแทนที่ทั้งไฟล์ | **ไม่ถูกแตะเลย** |
| ตรวจได้ไหม | `pnpm erp doctor` บอกว่ายังตรงกับที่ GO Along ทดสอบทุกไฟล์ | test ของคุณใน `ext/test/` รันใน `pnpm check` |

ผลคือ ลูกค้าได้ทั้งความยืดหยุ่น (แก้ตามงานจริงได้ทันทีด้วย AI) และความถูกต้อง (ฐานยังเป็นของที่ผ่านการทดสอบ และอัปเดตต่อได้โดยไม่ต้อง merge มือ)

## ต่อยอดได้แค่ไหนโดยไม่แตะโค้ดหลัก

ทุกอย่างอยู่ในโฟลเดอร์ `services/<โมดูล>/ext/` ระบบโหลดเองอัตโนมัติ

| อยากได้ | ทำใน ext/ | ตัวอย่าง |
|---|---|---|
| เพิ่มช่องข้อมูลในเอกสารเดิม | `migrations/00N_x_….sql` (`add column x_…`) + route `/x/…` + `ui.ts` เพิ่มคอลัมน์/ปุ่ม | รหัสงบประมาณบน PO |
| กฎของบริษัท | **guard** บน route เดิม — ปฏิเสธพร้อมข้อความไทย | PO เกิน 50,000 ต้องมีงบที่ยังเหลือ |
| ทำอะไรเมื่อเกิดเหตุการณ์ในโมดูลอื่น | **handler** รับ event เดิม | ออก NCR แล้วแจ้งกลุ่ม LINE ฝ่ายจัดซื้อ |
| รายงาน/หน้าจอใหม่ในโมดูลเดิม | GET `/x/…` + หน้าจอใหม่ใน `ui.ts` | งบคงเหลือรายแผนก |
| ซ่อนคอลัมน์/ปุ่มที่บริษัทไม่ใช้ | `ui.ts` → `hide` | ซ่อนสกุลเงินใน PO |
| งานใหม่ทั้งระบบ (เอกสาร/ตารางของตัวเอง) | โมดูลใหม่ `pnpm erp new-module` (`/new-module`) | ระบบจัดการแม่พิมพ์ |
| บั๊กหรือพฤติกรรมของฐานผิด | **แจ้ง GO Along** (โทร 085 608 3298 · sales@goalong.co.th) — แก้ในรุ่นถัดไปให้ทุกบริษัท | สูตรภาษีผิด |

ตัวอย่างครบชุดที่ทดสอบแล้ว: [`docs/examples/purchasing-budget/ext/`](examples/purchasing-budget/ext/) — copy ไปไว้ที่

## สั่ง AI อย่างไร

เปิดโปรเจกต์ใน AI coding tool แล้วพิมพ์ (คำสั่งสำเร็จรูปอยู่ใน `.claude/commands/`):

- `/extend purchasing ใบสั่งซื้อเกิน 100,000 ต้องแนบใบเสนอราคา 3 ใบก่อนอนุมัติ`
- `/extend quality เมื่อออก NCR ระดับวิกฤต ให้แจ้ง LINE กลุ่มผู้บริหาร`
- `/extend inventory เพิ่มช่อง "ตำแหน่งชั้นวาง" ในสินค้า และแสดงในรายการ stock`
- `/new-module mold แม่พิมพ์: ทะเบียน, รอบการใช้งาน, แจ้งเตือนครบรอบซ่อม`
- `/check` — รัน test ทั้งหมดและแก้จนผ่าน
- `/upgrade <โฟลเดอร์รุ่นใหม่>` — รับอัปเดตจาก GO Along

AI อ่าน `CLAUDE.md` (แผนที่ระบบ + ตาราง "Where a change goes" + กฎเหล็ก), `services/<โมดูล>/CLAUDE.md` (ข้อมูล, API, event ของโมดูล)
และ `CUSTOM.md` (ธรรมเนียมของบริษัทคุณ — เขียนเพิ่มได้เลย อัปเดตไม่ทับ)

## สิ่งที่ระบบกันไว้ให้ (AI ทำพลาดแล้วรู้ทันที ไม่เงียบ)

- guard ที่ชี้ไป route ที่ไม่มีแล้ว (เช่นรุ่นใหม่เปลี่ยนชื่อ) → service ไม่ยอม start
- `ui.ts` ที่ patch หน้าจอ/คอลัมน์ที่ไม่มีแล้ว → `pnpm erp ui-sync` และ test ล้มพร้อมบอกว่าตรงไหน
- route ใน ext ทับ route เดิม → ไม่ยอม start (ต่อยอดได้ ทับไม่ได้)
- handler ไม่ตรงกับ `ext.json` · permission ไม่ขึ้นต้นด้วยชื่อโมดูล · event ที่ไม่มีในสัญญา → error ตอน start/test
- ตารางใหม่ไม่มี `tenant_id` + `-- @tenant` → `pnpm erp verify` ไม่ผ่าน (ข้อมูลแต่ละบริษัทต้องแยกกันเสมอ)
- ตั้งชื่อไม่ขึ้นต้น `/x/` หรือ `x_` → เตือน (ป้องกันชนกับของที่ GO Along จะเพิ่มในอนาคต)
- แก้ไฟล์โค้ดหลัก → `pnpm erp verify` เตือน, `pnpm erp doctor` แสดงรายการไฟล์ (`verify --strict` ให้ล้มเลย — แนะนำให้ใส่ใน CI)

## อัปเดตจาก GO Along

```bash
pnpm erp upgrade ../erp-release-0.4          # ดูแผนก่อน (ไม่เปลี่ยนอะไร)
pnpm erp upgrade ../erp-release-0.4 --apply  # แทนที่ไฟล์โค้ดหลักที่ไม่ได้แก้ / ไม่แตะ ext/ และโมดูลของคุณ
pnpm install && pnpm erp ui-sync && pnpm check
```

ถ้าเคยแก้ไฟล์โค้ดหลักและรุ่นใหม่ก็แก้ไฟล์เดียวกัน ระบบเก็บของคุณไว้ แล้ววางรุ่นใหม่ไว้ที่ `.erp/upgrade/<path>` ให้ AI (`/upgrade`) ช่วยรวม —
ทางที่ดีกว่าคือย้ายการแก้นั้นเข้า `ext/` ครั้งเดียวจบ

## กติกาที่ต้องรักษา

1. ต่อยอดใน `ext/` หรือโมดูลใหม่เท่านั้น — `pnpm erp doctor` ต้องขึ้น "Vendor base intact"
2. ห้ามให้โมดูลหนึ่ง import หรือ query DB ของอีกโมดูล — ใช้ event
3. migration ห้ามแก้ไฟล์เก่า เพิ่มไฟล์ใหม่เสมอ (ทั้งของ GO Along และของคุณ)
4. ของใหม่ต้องมี test ใน `ext/test/` (รวม test สิทธิ์ 403 และการแยกข้อมูลระหว่างบริษัท)
5. รัน `pnpm check` ให้ผ่านก่อน commit ทุกครั้ง
