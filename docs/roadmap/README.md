# Roadmap 1,000 ฟังก์ชัน — Factory OS

> เอกสารภายใน GO Along (โฟลเดอร์ `docs/roadmap/` ใช้วางแผน ไม่ใช่สัญญากับลูกค้า) · ตัวเลขทุกตัวในไฟล์นี้คำนวณจาก [`functions.json`](functions.json) ณ 2 ต.ค. 2569 (อัปเดตหลังสร้าง 9 โมดูลใหม่เสร็จ: building → done)

## ไฟล์นี้คืออะไร

`functions.json` คือรายการ "สิ่งที่ผู้ใช้ทำได้" 1,000 ข้อ ครอบคลุมสิ่งที่มีแล้ว สิ่งที่กำลังสร้าง และสิ่งที่วางแผนไว้ ใช้เป็นภาษากลางของทีมขาย ทีมพัฒนา และลูกค้า เวลาคุยว่า "ระบบทำ X ได้ไหม" ให้ตอบเป็นเลข F ได้ทันที

| ฟิลด์ | ความหมาย |
|---|---|
| `id` | `F0001`–`F1000` เรียงตามโมดูล ห้ามนำเลขที่ใช้แล้วกลับมาใช้ใหม่ ฟังก์ชันใหม่ต่อท้ายที่ `F1001` |
| `module` | id ของโมดูลจริงใน `services/` หรือ id ที่เสนอสำหรับโมดูลใหม่ (มีเครื่องหมาย * ในตารางด้านล่าง) · `platform` = kernel/gateway/เว็บ/มือถือ · `tools` = `pnpm erp` และหน้าเว็บขาย · `ai` = ฟีเจอร์ AI ข้ามโมดูล |
| `area` | หมวดย่อยภายในโมดูล (ภาษาไทย) |
| `name` | สิ่งที่ผู้ใช้ทำได้ เขียนเป็นภาษาผู้ใช้ ไม่ซ้ำกันทั้งไฟล์ |
| `industries` | กลุ่มธุรกิจที่ได้ประโยชน์ (`all` = ทุกธุรกิจ) ใช้กรองทำเอกสารขายรายอุตสาหกรรม |
| `priority` | P1 = ลูกค้าเป้าหมายต้องมีก่อนซื้อ/ก่อนเลิกใช้ Excel · P2 = ทำให้ใช้งานลื่นหรือขายต่อได้ · P3 = ทำเมื่อมีลูกค้าขอและจ่าย |
| `status` | `done` = มีในโค้ดวันนี้ (ตรวจกับ route ใน `service.ts` และหน้าจอใน `ui.ts` แล้ว) · `building` = 9 โมดูลที่กำลังสร้าง · `planned` = ยังไม่เริ่ม |
| `effort` | S ≤ 2 วัน-คน · M 3–10 วัน-คน · L > 10 วัน-คน (ประมาณสำหรับทีมที่ใช้ Claude Code ช่วย) |

**กติกาการแก้ไฟล์:** เปลี่ยน `status` เป็น `done` ได้ก็ต่อเมื่อ `pnpm check` ผ่านและมีหน้าจอหรือ action ใน `ui.ts` แล้วเท่านั้น ฟังก์ชันที่ลูกค้าขอเฉพาะราย (งาน custom) ไม่ต้องใส่ไฟล์นี้ ยกเว้นตั้งใจจะขายซ้ำ
