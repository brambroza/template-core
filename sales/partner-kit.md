## 3. สคริปต์เดโมตามอุตสาหกรรม

> **กติกาเดโม:** ใช้เดโมเซิร์ฟเวอร์ของคุณ (ล้างข้อมูลได้เอง) **เลือกข้อมูลตรงธุรกิจลูกค้าเสมอ** — ผู้ซื้อจริงทั้ง 3 รายบอกว่าเดโมผิดอุตสาหกรรมทำให้เขาคิดว่า "ไม่ใช่ของเรา" ตั้งแต่ 5 วินาทีแรก · เปิด AI ก่อนเดโม (ใส่ key) หรือไม่ต้องพูดถึง AI เลย — **ห้ามให้ลูกค้าเห็นข้อความ "ใส่ API key"** · ให้ลูกค้าพิมพ์คำสั่งบน **มือถือของเขาเอง** · จบทุกเดโมด้วยข้อเสนอ 3 ทาง: ซื้อขาด / เช่า / Pilot 60 วัน

## 4. NFR และเดโมเซิร์ฟเวอร์

- **NFR = Not For Resale:** ใช้ภายในบริษัทคุณเท่านั้น ห้ามขายหรือให้ลูกค้าใช้ · ได้รุ่นใหม่ตลอดอายุสัญญาพาร์ทเนอร์ · หมดสัญญาแล้วซื้อขาดได้ในราคาพาร์ทเนอร์
- **ทำไมต้องใช้เอง:** ผู้ซื้อถามทุกรายว่า "มีใครใช้จริงไหม" — ระบบของคุณเองคือกรณีศึกษาที่ดีที่สุด และเป็นที่ฝึกทีมก่อนติดตั้งให้ลูกค้า
- **เดโมเซิร์ฟเวอร์:** บนคลาวด์ GO Along แยกบริษัทของคุณ · ข้อมูลตัวอย่าง 3 ชุด (โรงงาน / สำนักงาน / บริษัทบริการ) · ล้างข้อมูลและโหลดใหม่ได้เอง · ใส่ชื่อ/โลโก้ลูกค้าเป้าหมายได้ · บัญชีตัวอย่าง admin@, tech@, store@, qc@, buyer@, hr@, sales@, it@
- **สิ่งที่ต้องทำก่อนทุกเดโม:** อัปเดตเดโมเซิร์ฟเวอร์เป็นรุ่นล่าสุด · ตั้ง LINE token กลุ่มทดสอบ · เปิด AI (หรือไม่พูดถึง) · ตรวจว่าไม่มียอดสต็อกติดลบในข้อมูลเดโม

## 5. หลักสูตรอบรม

### 5.1 ขาย + เดโม (1 วัน — ตัวแทนขาย, ออนไลน์ 2 ชม. สำหรับผู้แนะนำ)
1. Factory OS คืออะไร: แยกโมดูลจริง ซื้อขาด/เช่า/pilot ไม่คิดรายหัว (1 ชม.)
2. ลูกค้าแต่ละกลุ่มเจ็บตรงไหน — อ่านรีวิวผู้ซื้อจริง 3 ราย (1 ชม.)
3. ฝึกสคริปต์เดโมข้อ 3 ทีละคน บนมือถือ (2 ชม.)
4. ตอบข้อโต้แย้งตาม [`objection-handling.md`](objection-handling.md) — ฝึกพูด "ยังไม่มี" พร้อมวันที่ (1 ชม.)
5. ออกใบเสนอราคา 3 ทาง + ลงทะเบียนดีล + เขียนเกณฑ์ pilot (1 ชม.)
6. **สอบ:** เดโม 15 นาทีให้ทีม GO Along ดู

### 5.2 Certified Implementer (2 วัน — พาร์ทเนอร์ติดตั้ง)
**วันที่ 1 — ติดตั้งและ go-live**
1. สถาปัตยกรรม: โมดูล = microservice + ฐานข้อมูลของตัวเอง, gateway, event outbox, RLS แยกบริษัท
2. ติดตั้งจริง: `pnpm erp compose <ชุด>` บน VPS/เซิร์ฟเวอร์ลูกค้า, HTTPS, สำรอง/กู้คืนข้อมูล
3. ไลเซนส์: `pnpm erp pack … --license`, การต่อแผนอัปเดต
4. ตั้งค่าบริษัท ผู้ใช้ บทบาทสำเร็จรูป ผังองค์กร สายอนุมัติ LINE แจ้งเตือน
5. นำเข้าข้อมูลหลัก + ยอดยกมา, นับสต็อกวันเริ่มระบบ, checklist go-live ≤ 3 สัปดาห์
6. Lab: ติดตั้ง `smart-maintenance` ตั้งแต่ศูนย์จนช่างแจ้งซ่อมจากมือถือได้

**วันที่ 2 — ซัพพอร์ตและต่อยอดด้วย AI**
1. ซัพพอร์ตระดับแรก: รับเรื่องผ่าน helpdesk ของ GO Along, SLA 4 ชม. ทำการ, เมื่อไรส่งต่อระดับสอง
2. อัปเกรดรุ่นด้วย skill `upgrade` โดยไม่ทับงานที่ต่อยอด
3. ต่อยอดตามกฎ: อ่าน `CLAUDE.md` ทุกโมดูล · `pnpm erp new-module` · หน้าจอใน `src/ui.ts` · event ผ่าน contracts · `pnpm check`
4. Lab: สร้างโมดูลเฉพาะลูกค้า 1 ตัวด้วย Claude Code ให้ผ่าน `pnpm erp verify`
5. **สอบ:** ติดตั้ง + ต่อยอด 1 ฟีเจอร์ + อัปเกรดหนึ่งรุ่น ภายใน 3 ชม.

## 6. สิ่งที่ห้ามพูด / ห้ามทำ
- ใบกำกับมีข้อมูลผู้ขายครบแล้ว (0.3.0) — แต่ลูกค้ารายใหญ่ที่ต้องส่งเอกสารเป็น PDF แนบอีเมลทุกใบ ให้รอ PDF/อีเมล 0.3.x ธ.ค. 2569 หรือเขียนวันที่ลงสัญญา pilot (ตัวแทนขายรายแรกพูดเอง: "ถ้าลูกค้าเจอเอกสารไม่เรียบร้อย ชื่อเสียผมเสียก่อน GO Along")
- บัญชี เงินเดือน สัญญา MA **มีแล้วระดับ MVP** — ขายได้ แต่ห้ามพูดว่า "ยื่นภาษีออนไลน์ได้" "ไม่ต้องใช้โปรแกรมบัญชีอื่นแล้ว" หรือ "แอปช่างภาคสนามครบ" · สิ่งที่ยังไม่มีต้องมีวันที่เสมอ — วันที่ที่ใช้ได้: 0.3.x ธ.ค. 2569 · 0.4 มี.ค. 2570 (e-Filing, e-Tax, เจ้าหนี้/ภ.ง.ด.3/53, ธนาคาร) · 0.5 มิ.ย. 2570 (ภาคสนามเต็มรูป, LINE OA ลูกค้า)
- ห้ามรวมส่วนลด (pilot + ส่วนลดพาร์ทเนอร์เพิ่ม, เช่า + ส่วนลด)
- ห้ามแก้ kernel ในเครื่องลูกค้า — ต่อยอดเป็นโมดูลใหม่หรือ migration ใหม่เท่านั้น (ไม่อย่างนั้นอัปเดตไม่ได้และหลุดจากซัพพอร์ต)
