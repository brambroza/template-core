# Pilot Kit — ชุดเครื่องมือสำหรับ pilot 3 รายแรกของ Factory OS

> เอกสารภายใน GO Along (โฟลเดอร์ `sales/` ไม่ถูกแพ็กส่งลูกค้า) · ฉบับ 3 ต.ค. 2569 · ใช้กับ Factory OS 0.3.0
> ทำขึ้นเพื่อ [`launch-checklist.md`](../launch-checklist.md) ข้อ 2 (หาผู้มุ่งหวังจริง 3 ราย) และข้อ 3 (เดโม + ทดสอบสมมติฐานราคา)
>
> ⚠️ **GO Along ยังไม่มีลูกค้าจริงและยังไม่มี pilot** — คุณวิทยา คุณนภาพร คุณธีรพงษ์ และคุณสุภาวดีใน [`../feedback/`](../feedback/) เป็น **รีวิวจำลอง (AI persona) — ใช้เป็นสมมติฐาน ต้องยืนยันกับลูกค้าจริง** ห้ามเอ่ยชื่อหรือคำพูดของ persona กับผู้มุ่งหวัง ห้ามพูดว่า "โรงงาน/บริษัทอื่นตกลงแล้ว" ให้เสนอเป็น **pilot partner รายแรก ๆ** เท่านั้น

## 1. ชุดนี้คืออะไร (What this kit is)

ชุดเอกสาร 5 ไฟล์ที่พาเจ้าของจาก "รายชื่อผู้มุ่งหวัง" ไปจนถึง "ตัดสินใจซื้อ/เช่าหลังจบ pilot 60 วัน" โดยยึดของที่ระบบทำได้จริงวันนี้ (ตรวจกับ `services/*/src/ui.ts`, `services/*/CLAUDE.md` และ `catalog/catalog.json` แล้ว)

| ไฟล์ | ใช้ตอนไหน | ได้อะไร |
|---|---|---|
| [`discovery-scorecard.md`](discovery-scorecard.md) | ก่อนนัดเดโม / หลังโทรคุย 15 นาที | คะแนน 0–15 + ข้อตัดสิทธิ์ ว่าควรเสนอ pilot หรือไม่ |
| [`demo-scripts.md`](demo-scripts.md) | เดโม 30 นาที | 3 สคริปต์คลิกต่อคลิก (โรงงาน · สำนักงาน/HR/เงินเดือน/ทรัพย์สิน · บริการ/สัญญา MA) + คำถาม discovery + วิธีถามราคาแบบไม่ชี้นำ |
| [`pilot-agreement-outline.md`](pilot-agreement-outline.md) | หลังลูกค้าเลือก "pilot" | โครงสัญญา pilot แบบภาษาง่าย (**ร่าง — ต้องให้ทนายไทยตรวจก่อนใช้**) |
| [`onboarding-runbook.md`](onboarding-runbook.md) | สัปดาห์ 0–6 ของ pilot | ขั้นตอนรายสัปดาห์ นำเข้าข้อมูล บทบาท อบรม go-live เช็กอินรายสัปดาห์ ตัวชี้วัด |
| README นี้ | ก่อนเริ่ม | ลำดับการใช้ กติกา และสิ่งที่เจ้าของต้องตัดสินใจก่อน pilot แรก |

## 2. ลำดับการใช้ (How to use)

```
รายชื่อ (launch-checklist ข้อ 4) → โทรคัดกรอง 15 นาที + discovery-scorecard
   → คะแนน ≥ 12 และไม่มีข้อตัดสิทธิ์ → นัดเดโม 30 นาที (demo-scripts) ภายใน 7 วัน
   → ใบเสนอราคา 3 ทางภายใน 24 ชม. (`pnpm erp quote <ชุด> --rent --pilot`)
   → ลูกค้าเลือก pilot → ร่างสัญญาจาก pilot-agreement-outline (ผ่านทนายแล้ว) + เอกสาร must-have พร้อมวันที่
   → onboarding-runbook สัปดาห์ 0–6 + เช็กอินทุกสัปดาห์
   → วันที่ 60: วัดผลตามเกณฑ์ → ซื้อขาด / เช่า / ยกเลิก (ภายใน 30 วันหักค่า pilot คืน 100%)
```

**ทุกเดโมและทุกการคุยราคา → จดลง CRM ของเรา** (ช่องที่ต้องมีอยู่ใน `demo-scripts.md` ข้อ 5) แล้วเทียบกับสมมติฐานจากรีวิวจำลองใน `business-model.md` ข้อ 0.2 **หลังจบการคุยเท่านั้น**

## 4. กติกาที่ต้องถือ (Ground rules)

1. **สถานะฟีเจอร์ใช้ 4 ระดับเท่านั้น:** มีแล้ว · 0.3.x ธ.ค. 2569 · 0.4 มี.ค. 2570 · 0.5 มิ.ย. 2570 · ยังไม่มีรุ่น ([`objection-handling.md`](../objection-handling.md)) — ห้ามพูด "เร็ว ๆ นี้" ห้ามพูด "ยื่นภาษีจากระบบได้" "แทนโปรแกรมบัญชี" "รู้กำไรทุกโครงการ"
2. **สิ่งที่ยังไม่มีแต่ลูกค้าต้องการก่อน go-live = เขียนลงเอกสาร must-have พร้อมวันที่** — ถ้า GO Along ส่งไม่ทันจนไม่ผ่านเกณฑ์ คืนเงิน 50% (กติกา `pilot` ใน catalog)
3. **ห้ามลดซ้อน:** pilot + ส่วนลดเซลส์ หรือ เช่า + ส่วนลด ไม่ได้ (ยกเว้นจ่ายเช่าล่วงหน้า 12 เดือนลด 10%) · ส่วนลดเซลส์ ≤ 10% ใช้กับซื้อขาดเท่านั้น
4. **กำลังคน:** pilot จำกัด 2 รายต่อชุด และไม่เกิน 6 รายพร้อมกัน ไม่เกิน 7 โมดูลต่อ pilot — สำหรับ 3 รายแรก **แนะนำให้เริ่มห่างกัน 1–2 สัปดาห์** เพราะสัปดาห์ 1–2 ของแต่ละรายใช้คนมากที่สุด
5. **ห้ามเดโมก่อน QA เขียว:** launch-checklist บอกว่าห้ามขึ้นเดโมเซิร์ฟเวอร์ใหม่จนกว่า `pnpm check` + `pnpm uat:pack` ผ่าน แล้วไล่ "ตรวจ 6 จุด" (launch-checklist ข้อ 2) ก่อนเดโมแรกทุกครั้งที่ reset ข้อมูล

## 7. เกณฑ์ว่า pilot ชุดนี้ "สำเร็จ" สำหรับ GO Along (ไม่ใช่สำหรับลูกค้า)

- ได้ปฏิกิริยาราคาจริง 3 ราย (ยอมรับ/ต่อรอง/ปฏิเสธ + เหตุผลเป็นคำพูดจริง) ลง CRM — launch-checklist ข้อ 3
