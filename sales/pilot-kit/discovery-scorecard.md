# Discovery Scorecard — คัดผู้มุ่งหวังก่อนเสนอ pilot

> เอกสารภายใน GO Along · ฉบับ 3 ต.ค. 2569 · ใช้หลังโทรคัดกรอง 15 นาที (คำถามใน [`demo-scripts.md`](demo-scripts.md) ข้อ 1) และอัปเดตอีกครั้งหลังเดโม
> เหตุผลที่ต้องคัด: pilot จำกัด 2 รายต่อชุดและ 6 รายพร้อมกัน และแต่ละรายใช้คนของเราหลายวัน — pilot ที่ไม่มี champion หรือข้อมูลไม่พร้อม จะ "ไม่ผ่านเกณฑ์" ด้วยเหตุที่ไม่เกี่ยวกับระบบ และไม่ได้บทเรียนราคาที่ต้องการ

---

## 1. วิธีให้คะแนน

5 ด้าน × 0–3 คะแนน = เต็ม 15 · ให้คะแนนจาก **หลักฐาน (สิ่งที่ลูกค้าพูด/ส่งมา)** ไม่ใช่ความรู้สึก · ไม่แน่ใจ = ให้คะแนนต่ำกว่า

| คะแนนรวม | ทำอะไรต่อ |
|---|---|
| **12–15** และไม่มีด้านไหนได้ 0 และไม่มีข้อตัดสิทธิ์ | เสนอ pilot / เช่า ได้ทันทีหลังเดโม |
| **9–11** | เดโมได้ แต่ก่อนเสนอ pilot ต้องยกด้านที่ต่ำสุดขึ้นก่อน (เช่น ขอไฟล์ข้อมูลตัวอย่าง, นัดผู้ตัดสินใจ) |
| **≤ 8** หรือ ด้าน "ความเจ็บปวด" / "champion" ได้ 0 | ไม่เสนอ pilot ตอนนี้ — ชวนเข้า webinar/ติดตามข่าวรุ่นถัดไป · ยังจดปฏิกิริยาราคาได้ถ้าได้เดโมแล้ว |
| มี **ข้อตัดสิทธิ์** (ข้อ 3) แม้แต่ข้อเดียว | ไม่เสนอ pilot จนกว่าข้อนั้นหายไป (ลูกค้าเปลี่ยนความต้องการ หรือรุ่นที่มีฟีเจอร์ออกแล้ว) |

## 2. เกณฑ์ 5 ด้าน (0–3)

### 2.1 ความเหมาะสม (Fit) — งานของเขาตรงกับของที่ระบบทำได้ **วันนี้** แค่ไหน

| คะแนน | หลักฐาน |
|---|---|
| 0 | ปัญหาหลักอยู่นอกสิ่งที่ระบบทำ หรือต้องการ > 7 โมดูลใน pilot หรือ > 100 ผู้ใช้บนแบบเช่า |
| 1 | ตรงบางส่วน แต่งานหลักต้องพึ่งของรุ่น 0.3.x/0.4 |
| 2 | ตรงกับชุดเป้าหมาย (`smart-maintenance` / `office-payroll`+`assets` / `service-ma`) ช่องว่างที่เหลือเป็น "ดีถ้ามี" |
| 3 | ตรงกับโปรไฟล์ในสมมติฐาน (launch-checklist ข้อ 2: โรงงานปั๊ม/ชิ้นส่วน 50–200 คน · บริษัทการค้า/บริการ 30–80 คนทำเงินเดือนใน Excel · บริษัทไอที/CCTV มีสัญญา MA) และทุก must-have มีในระบบแล้ว |

### 2.2 ความเจ็บปวด (Pain) — มีปัญหาที่วัดได้และอยากแก้ตอนนี้

| คะแนน | หลักฐาน |
|---|---|
| 0 | "อยากดูไว้ก่อน" ไม่มีปัญหาเฉพาะ |
| 1 | บอกปัญหาได้ แต่ไม่มีตัวเลข และไม่มีเหตุให้ต้องแก้เร็ว |
| 2 | บอกตัวเลขได้ 1 ตัว (เช่น เครื่องหยุด ~__ ชม./เดือน, เอกสารค้าง __ วัน, PM หลุด __ งาน) |
| 3 | มีตัวเลข + มีเหตุเร่ง (audit ลูกค้า, เปลี่ยนคนทำเงินเดือน, สัญญา MA ใหม่, ลูกค้ารายใหญ่ตีกลับเอกสาร) ภายใน 3 เดือน |

### 2.3 งบประมาณและการอนุมัติ (Budget)

| คะแนน | หลักฐาน |
|---|---|
| 0 | ไม่มีงบ และไม่รู้ว่าใครอนุมัติ |
| 1 | "ต้องไปตั้งงบปีหน้า" หรือผู้อนุมัติต้องเข้าบอร์ดและยังไม่ได้คุย |
| 2 | รู้กระบวนการอนุมัติ และวงเงินที่อนุมัติเองได้ครอบคลุมทางใดทางหนึ่งใน 3 ทาง (pilot / เช่า / ซื้อขาด) |
| 3 | ผู้ตัดสินใจอยู่ในเดโมหรือนัดได้ภายใน 7 วัน + จ่ายซอฟต์แวร์แบบนี้มาแล้ว (ก้อนหรือรายเดือน) |

> ถามแบบไม่ชี้นำ: "ใครเซ็น / อนุมัติเองได้ถึงประมาณเท่าไร / ซอฟต์แวร์ล่าสุดจ่ายแบบไหน" — **อย่าบอกราคาของเราในขั้นนี้** (ดูวิธีทดสอบราคาใน `demo-scripts.md` ข้อ 2.1 / 3.1 / 4.1)

### 2.4 ผู้ผลักดันภายใน (Champion)

| คะแนน | หลักฐาน |
|---|---|
| 0 | ไม่มีใครรับเป็นเจ้าของเรื่อง |
| 1 | มีคนสนใจ แต่ไม่มีเวลา/ไม่มีอำนาจสั่งให้ทีมใช้ |
| 2 | มีคนรับเป็น champion มีเวลา ≥ 2 ชม./สัปดาห์ และหัวหน้ารู้เรื่อง |
| 3 | champion มีอำนาจกำหนดกติกา "งานนี้ต้องเข้าระบบ" (เช่น ผู้จัดการโรงงาน/หัวหน้าช่าง/ผู้จัดการ HR) + ตกลงประชุม 30 นาทีทุกสัปดาห์ |

### 2.5 ความพร้อมของข้อมูล (Data readiness)

ดูว่าข้อมูลหลักเข้าระบบได้เร็วแค่ไหน — **หน้านำเข้า CSV มีเฉพาะ** สินค้า/อะไหล่, ลูกค้า/ผู้ขาย, ข้อมูลเงินเดือน, OT รายเดือน · เครื่องจักร ผู้ใช้ พนักงาน ทรัพย์สิน สัญญา MA ยอดยกมาสต็อก = คีย์หรือให้ทีมเราทำ (README ข้อ 5)

| คะแนน | หลักฐาน |
|---|---|
| 0 | ข้อมูลอยู่ในหัวคน/กระดาษ ไม่มีรายการ |
| 1 | มี Excel แต่กระจัดกระจาย รหัสซ้ำ/ไม่มีรหัส |
| 2 | มี Excel รายการหลักพร้อมรหัส (สินค้า/อะไหล่/ลูกค้า/พนักงาน) ส่งตัวอย่างได้ภายใน 1 สัปดาห์ |
| 3 | ส่งตัวอย่างไฟล์มาแล้ว และปริมาณที่ต้องคีย์มือ (เครื่องจักร/พนักงาน/สัญญา/ทรัพย์สิน) อยู่ในระดับที่ทำเสร็จใน 2–3 วันทำการ |

## 3. ข้อตัดสิทธิ์ (Knock-outs) — ไม่เสนอ pilot ถ้าลูกค้า **ต้องมีตั้งแต่วันแรก**

ตรวจกับ [`objection-handling.md`](../objection-handling.md) และ `docs/roadmap/README.md` (ถ้าเป็นรุ่น 0.3.x ที่ส่งทันในช่วง pilot ให้เขียนเป็น must-have พร้อมวันที่ได้ — ไม่ใช่ข้อตัดสิทธิ์)

- [ ] ยื่นภาษีจากระบบ: ภ.ง.ด.3/53, ไฟล์ e-Filing ภ.พ.30, e-Tax Invoice (0.4 มี.ค. 2570) หรือใช้เป็นสมุดบัญชีหลักแทนโปรแกรมบัญชี
- [ ] ย้อนล็อต/Heat no. จากชิ้นงานถึงวัตถุดิบ (0.4)
- [ ] แอปช่างภาคสนามเต็มรูป: ลายเซ็นลูกค้าบนจอ, เช็กอิน GPS, แผนที่, รูปในใบงาน PM (0.5 มิ.ย. 2570)
- [ ] ไฟล์โอนเงินเดือนรูปแบบธนาคาร / ไฟล์ยื่น สปส. ออนไลน์ (0.4) และไม่ยอมใช้ CSV ชั่วคราว
- [ ] ticket ผูกสัญญา MA + SLA 24x7 ตามสัญญา (0.3.x ธ.ค. 2569) **และ** pilot ต้องเริ่มก่อน ธ.ค.
- [ ] PM ตามชั่วโมงเครื่อง/shot, OEE/MES, ตารางผลิตตามเครื่อง (ยังไม่มีรุ่น)
- [ ] กำไรต่อโครงการ / ต้นทุนแรงงาน-โสหุ้ยจริง (0.4 / ยังไม่มีรุ่น)
- [ ] ระบบประเมินผล รับสมัคร กะงาน สิทธิ์พักร้อนตามอายุงาน (ยังไม่มีรุ่น)
- [ ] เชื่อม Express/โปรแกรมบัญชีอัตโนมัติ (ส่งออกรูปแบบ Express = 0.4, เชื่อมเต็มรูป = ยังไม่มีรุ่น)
- [ ] ต้องติดตั้งบนเซิร์ฟเวอร์ลูกค้าตั้งแต่ pilot แต่ไม่มีคนดูแลเซิร์ฟเวอร์ (pilot ของเรารันบนคลาวด์ GO Along)
- [ ] ต้องการ > 7 โมดูลใน pilot · หรือ > 100 ผู้ใช้บนแบบเช่า
- [ ] ผู้ตัดสินใจไม่ยอมพบภายใน 30 วัน
- [ ] คาดหวังว่า "ลูกค้ารายอื่นใช้แล้ว" เป็นเงื่อนไขซื้อ (เรายังไม่มี — ให้ความจริงแล้วดูว่ายังสนใจเป็น pilot partner รายแรกไหม)

## 5. ตัวอย่างการให้คะแนน (สมมติ — ไม่ใช่ลูกค้าจริง)

| สถานการณ์ | Fit | Pain | Budget | Champion | Data | รวม | ผล |
|---|---|---|---|---|---|---|---|
| โรงงานฉีดพลาสติก 80 คน หัวหน้าช่างอยากเลิก LINE เครื่องหยุด ~12 ชม./เดือน เจ้าของอยู่ในเดโม อะไหล่อยู่ใน Excel มีรหัส | 3 | 3 | 3 | 3 | 2 | 14 | เสนอ pilot |
