## 2. ขอบเขต (Scope)

**2.1 โมดูลที่ใช้** — ระบุรายการ (ไม่เกิน 7 โมดูล ตาม `pilot.maxModules`) เช่น
- โรงงาน: `smart-maintenance` = ซ่อมบำรุง, คลังสินค้า, ระบบอัตโนมัติ (+ แพลตฟอร์มหลัก: ผู้ใช้และสิทธิ์, ข้อมูลหลัก)
- สำนักงาน: อนุมัติ, เบิกค่าใช้จ่าย, บุคคลและลงเวลา, จองห้องและรถ, เงินเดือน, ทะเบียนทรัพย์สิน
- บริการ: CRM, โครงการ, ขาย, เบิกค่าใช้จ่าย, ระบบอัตโนมัติ, สัญญา MA, แจ้งปัญหา

**2.2 สิ่งที่ GO Along ทำให้ (รวมในค่า pilot — จาก `pilot.includesTh`)**
1. ระบบบนคลาวด์ของ GO Along ตลอด 60 วัน (1 การติดตั้งเฉพาะลูกค้ารายนี้, HTTPS, สำรองข้อมูลรายวัน)
2. ติดตั้ง ตั้งค่าบริษัท/หัวเอกสาร ผู้ใช้ บทบาท และนำเข้าข้อมูลหลักและยอดยกมาจาก Excel ของลูกค้า **ตามแม่แบบของเรา และภายในจำนวนแถวที่ระบุ [ตัดสินใจ: เช่น ≤ 2,000 สินค้า, ≤ 500 คู่ค้า, ≤ 100 เครื่องจักร/สัญญา]** — ระบุให้ชัดว่าข้อมูลบางประเภท (เครื่องจักร, พนักงาน, ผู้ใช้, ทรัพย์สิน, สัญญา MA, ยอดยกมาสต็อก) ไม่มีหน้านำเข้าในระบบ GO Along จะคีย์หรือนำเข้าด้วยเครื่องมือของทีมให้
3. อบรม on-site 1 วัน + ช่วยใช้งานจริง 2 สัปดาห์แรก
4. ประชุมติดตามผล 30 นาทีทุกสัปดาห์
5. ตั้ง LINE OA แจ้งเตือน (ถ้าอยู่ในขอบเขต) — ลูกค้าเป็นเจ้าของบัญชี LINE OA เอง
6. ส่งมอบรายการ must-have ตามเอกสารแนบ ข (ถ้ามี) ภายในวันที่ระบุ

**2.3 สิ่งที่ไม่อยู่ในขอบเขต (เขียนให้ชัด — กันความคาดหวังเกิน)**
- งานพัฒนาเพิ่มเฉพาะลูกค้า (ถ้าต้องการ คิด 6,000 บาท/man-day ตาม `services.customDev` แยกสัญญา)
- การย้ายประวัติย้อนหลัง (ประวัติซ่อม, PO/SO เก่า) เว้นแต่ระบุในเอกสารแนบ
- ฟีเจอร์ที่ยังไม่มีในรุ่นปัจจุบัน — **แนบรายการ "ยังไม่มี" ที่เกี่ยวกับลูกค้ารายนี้พร้อมรุ่น** (ตัวอย่าง: ยื่นภาษี/e-Filing/e-Tax = 0.4 มี.ค. 2570 · ย้อนล็อต/Heat no. = 0.4 · แอปช่างภาคสนามเต็มรูป = 0.5 มิ.ย. 2570 · PM ตามชั่วโมงเครื่อง = ยังไม่มีรุ่น · ไฟล์โอนเงินเดือนรูปแบบธนาคาร = 0.4 · ticket ผูกสัญญา MA/SLA 24x7 = 0.3.x ธ.ค. 2569)
- ระบบนี้ **ไม่ใช่โปรแกรมยื่นภาษีและไม่ใช่สมุดบัญชีหลัก** ในช่วง pilot — ลูกค้ายังใช้โปรแกรมบัญชี/เงินเดือนเดิมคู่กัน (สำหรับ pilot เงินเดือน: แนะนำคำนวณคู่ขนานอย่างน้อย 1 รอบก่อนจ่ายจริงจากระบบ)
- คำรับประกันความถูกต้องของอัตราตามกฎหมาย (ภาษี/ประกันสังคม) **ยังไม่รวมในสัญญา pilot จนกว่าเอกสารที่ทนายตรวจแล้วจะออก** (launch-checklist ข้อ 5ข) — ห้ามสัญญาด้วยวาจา

**2.4 ผู้ใช้:** ไม่จำกัดจำนวนในขอบเขต fair use ≤ 100 ผู้ใช้ (`rental.userLimit`) · login ด้วยอีเมล · ผู้ดูแลของลูกค้าตั้งรหัสผ่านเริ่มต้น (ยังไม่มีหน้าเปลี่ยน/ลืมรหัสผ่าน — GO Along รีเซ็ตให้เมื่อขอ)

## 3. ระยะเวลา (Duration)

- 60 วันปฏิทิน (`pilot.durationDays`) **นับจากวันที่ระบบพร้อมใช้และอบรม on-site เสร็จ (วัน go-live)** ไม่ใช่วันเซ็น — **[ตัดสินใจ]** เพราะถ้าลูกค้าส่งข้อมูลช้า 60 วันจะหมดก่อนได้ใช้จริง
- กำหนดเส้นตายส่งข้อมูลของลูกค้า (เช่น ภายใน 10 วันทำการหลังเซ็น) ถ้าเกิน GO Along เลื่อนวัน go-live ได้ แต่ไม่เกิน ___ วัน **[ตัดสินใจ]**
- ขยายเวลาได้ครั้งเดียว ≤ 30 วัน เมื่อทั้งสองฝ่ายตกลงเป็นลายลักษณ์อักษร (ไม่มีค่าใช้จ่ายถ้าสาเหตุมาจาก GO Along) **[ตัดสินใจ]**

## 6. ข้อมูลของลูกค้า (Data ownership & PDPA)

- **ข้อมูลทั้งหมดที่ลูกค้าบันทึกเป็นของลูกค้า** GO Along ใช้เพื่อให้บริการ pilot เท่านั้น
- GO Along เป็น **ผู้ประมวลผลข้อมูลส่วนบุคคล** แทนลูกค้า (ผู้ควบคุมข้อมูล) ตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล — **[ทนาย] ต้องมีข้อตกลงการประมวลผลข้อมูล (DPA) แนบ** โดยเฉพาะ pilot ที่มีข้อมูลพนักงาน/เงินเดือน/พิกัด GPS
- ข้อเท็จจริงที่ระบุได้: ระบบไม่เก็บเลขบัตรประชาชน และเก็บเลขบัญชีธนาคารแค่ 4 หลักท้าย · หน้าขอความยินยอมสำหรับ GPS ลงเวลายังไม่มีในระบบ (ลูกค้าใช้แบบฟอร์มยินยอมของตัวเอง) · แยกข้อมูลแต่ละบริษัทด้วย row-level security ในฐานข้อมูล และ pilot แต่ละรายอยู่บนการติดตั้งแยกกัน
- การส่งออก: ทุกหน้ารายการส่งออก CSV ได้ตลอด pilot · เมื่อจบ pilot ลูกค้าขอไฟล์ข้อมูลทั้งหมดได้ (CSV ต่อหน้ารายการ และ/หรือไฟล์สำรองฐานข้อมูล) ภายใน ___ วัน **[ตัดสินใจ]**
- การลบ: ถ้าไม่ต่อ GO Along ลบข้อมูลและไฟล์สำรองภายใน ___ วันหลังส่งมอบไฟล์ และยืนยันเป็นลายลักษณ์อักษร **[ตัดสินใจ/ทนาย]**
- การสำรองข้อมูล: รายวัน ทดสอบกู้คืนก่อน go-live (สคริปต์อัตโนมัติในซอฟต์แวร์ = 0.3.x — ระหว่างนี้ GO Along ตั้งเองบนเซิร์ฟเวอร์) — **ห้ามเขียนตัวเลข RPO/RTO จนกว่าจะซ้อมกู้คืนจริงแล้ว**
- AI: ถ้าลูกค้าเปิดผู้ช่วย AI ข้อความที่ถาม/รูปใบเสร็จที่สแกนจะถูกส่งไปยังผู้ให้บริการโมเดล AI ตาม key ของลูกค้า — **[ทนาย] ระบุในข้อตกลงข้อมูล**

## 7. สิทธิ์ใช้ซอฟต์แวร์และ source code (Licence) — ให้สอดคล้องกับ `docs/selling-and-licensing.md`

**7.1 ระหว่าง pilot:** สิทธิ์ใช้งานระบบผ่านเว็บ/มือถือบนเซิร์ฟเวอร์ของ GO Along เท่านั้น **ไม่มีการส่งมอบ source code** · สิทธิ์สิ้นสุดเมื่อจบ pilot (หรือเมื่อแปลงเป็นเช่า/ซื้อ)

**7.2 ถ้าแปลงเป็น "เช่ารายเดือน" (`rental`):** ใช้งานบนคลาวด์ multi-tenant ของ GO Along · ไม่ได้ source code · ไม่คิดรายหัว (≤ 100 ผู้ใช้) · สัญญาขั้นต่ำ 12 เดือน · จ่ายล่วงหน้า 12 เดือนลด 10% · **เช่าเพื่อเป็นเจ้าของ:** ภายใน 24 เดือน นำค่าเช่าที่จ่ายแล้ว 50% ไปลดราคาไลเซนส์ (ลดได้ไม่เกิน 50% ของราคาไลเซนส์)

**7.3 ถ้าแปลงเป็น "ซื้อขาด" (ไลเซนส์ source code):**
- ไลเซนส์ **ต่อ 1 นิติบุคคล ต่อ 1 การติดตั้ง** (`catalog.json` note) เฉพาะโมดูลที่ซื้อ ไม่มีวันหมดอายุ (ใบอนุญาตออกโดยไม่ใส่ `--expires`)
- ได้ source code เฉพาะโมดูลที่ซื้อ + kernel/contracts/thai + gateway + เอกสารสำหรับ AI + `deploy/` + smoke test (ผ่าน `pnpm erp pack`)
- **ลูกค้าแก้ไขและต่อยอดได้** (รวมถึงใช้ AI ช่วย) แนวทาง: ต่อยอดเป็นโมดูลใหม่หรือ migration ใหม่ ไม่แก้ kernel — ถ้าแก้ kernel/`packages/*` เอง GO Along อาจอัปเดตหรือซัพพอร์ตส่วนนั้นไม่ได้ **[ทนาย: ระบุขอบเขตซัพพอร์ตต่อโค้ดที่ลูกค้าแก้]**
- **ห้าม** ขายต่อ แจกจ่าย ให้สิทธิ์ช่วง หรือใช้กับนิติบุคคล/การติดตั้งอื่นโดยไม่ได้ซื้อเพิ่ม **[ทนาย]**
- รวมอัปเดต 12 เดือนแรก (`--updates-until`) · ตั้งแต่ปีที่ 2 แผนอัปเดต + ซัพพอร์ต 20%/ปีของราคาไลเซนส์ (`updatePlanPct`) **ไม่บังคับ** — ไม่ต่อก็ใช้รุ่นที่มีได้ตลอดไป แต่จะไม่ได้รุ่นใหม่และ **การปรับอัตราตามกฎหมาย** (ภาษี/ประกันสังคม)
- ซื้อโมดูลเพิ่มภายใน 12 เดือน: จ่ายเท่ากับราคาชุดที่ควรได้ ลบส่วนที่จ่ายไปแล้ว (upgrade credit)
- ใบอนุญาต (license token) เป็นตัวกำหนดขอบเขตตามสัญญา ไม่ใช่ระบบป้องกันการคัดลอก (ตาม `packages/kernel/src/license.ts`) — ขอบเขตการใช้ผูกด้วยสัญญานี้
- ทรัพย์สินทางปัญญา: GO Along เป็นเจ้าของซอฟต์แวร์และงานพัฒนาที่นำไปขายซ้ำได้ · โค้ดที่ลูกค้าเขียนเองเป็นของลูกค้า **[ทนาย: ถ้อยคำงาน custom ที่ GO Along ทำให้ลูกค้า — business-model ข้อ 4 #4 ระบุว่ากรรมสิทธิ์เป็นของ GO Along ต้องเขียนในสัญญา]**

## 8. หน้าที่ของลูกค้า (Customer commitments) — เงื่อนไขที่ทำให้ pilot วัดผลได้

- แต่งตั้ง **ผู้ประสานงานหลัก (champion)** 1 คน มีเวลา ≥ ___ ชม./สัปดาห์ และผู้ตัดสินใจเข้าประชุมวันเริ่มและวันสรุปผล
- ส่งข้อมูลตามแม่แบบภายในวันที่กำหนด และยืนยันความถูกต้องของข้อมูลที่นำเข้า (ผลลองนำเข้า/dry-run)
- ให้ผู้ใช้ที่ระบุเข้าอบรม และใช้ระบบกับงานจริงตามขอบเขต (เช่น แจ้งซ่อมทุกครั้งผ่านระบบ)
- ให้ feedback รายสัปดาห์ (`pilot.conditionsTh`)
- **กรณีศึกษา:** ยินยอมให้ GO Along ใช้ชื่อ โลโก้ และตัวเลขก่อน-หลัง **เฉพาะเมื่อผ่านเกณฑ์** และลูกค้าเห็นข้อความก่อนเผยแพร่ **[ตัดสินใจ: ขอสิทธิ์อนุมัติข้อความก่อนเผยแพร่ให้ลูกค้า]**

## 9. หน้าที่ของ GO Along และการซัพพอร์ต

- ช่องทางซัพพอร์ต: LINE กลุ่มโครงการ + อีเมล · เวลาทำการ จ.–ศ. ___ **[ตัดสินใจ]**
- เวลาตอบรับ: ปัญหาที่ทำให้งานหลักหยุด ≤ 4 ชม. ทำการ · อื่น ๆ ≤ 1 วันทำการ **[ตัดสินใจ — persona โรงงานขอ 4 ชม.; เขียนเฉพาะ "ตอบรับ" จนกว่าจะวัดเวลาแก้จริงได้]**
- แจ้งล่วงหน้าก่อนอัปเดตรุ่นที่กระทบการใช้งาน ≥ 1 วันทำการ
- การรักษาความลับข้อมูลทางธุรกิจของลูกค้าทั้งสองทาง **[ทนาย: NDA]**

## 10. เอกสารแนบ must-have และการคืนเงิน

- **เอกสารแนบ ข — must-have:** รายการฟังก์ชันที่ลูกค้าต้องมีก่อน/ระหว่าง pilot ที่ยังไม่มีในรุ่นปัจจุบัน แต่ละข้อมี เลขฟังก์ชัน (F…) รุ่น และวันส่งมอบ — ใช้วันที่ได้เฉพาะ 0.3.x ธ.ค. 2569 / 0.4 มี.ค. 2570 / 0.5 มิ.ย. 2570 ตาม `docs/roadmap/README.md` · ข้อที่ "ยังไม่มีรุ่น" ห้ามใส่เป็น must-have ของ pilot (ขายได้เฉพาะงานพัฒนาร่วมแยกสัญญา)
- **คืนเงิน 50%** (`refundPctIfCriteriaMissed`) และยกเลิกได้ทันที เมื่อไม่ผ่านเกณฑ์ **เพราะฟังก์ชันที่ GO Along สัญญาไว้ในเอกสารแนบ ข ไม่พร้อม** (`pilot.conditionsTh`)
- ไม่ผ่านเกณฑ์ด้วยเหตุอื่น (เช่น ลูกค้าไม่ส่งข้อมูล/ไม่ใช้งาน) → ไม่คืนเงิน **[ตัดสินใจ/ทนาย: นิยาม "เหตุจากลูกค้า"]**
- ถ้ารุ่นที่เขียนวันที่ไว้เลื่อนหลังลูกค้าซื้อแล้ว: ลูกค้าได้แผนอัปเดตฟรีเพิ่มเท่าจำนวนเดือนที่เลื่อน (นโยบายใน `objection-handling.md` ข้อ 6) **[ตัดสินใจ: ใช้กับลูกค้าตรงด้วยหรือไม่]**

## 11. การสิ้นสุดและทางออก (Exit)

| สถานการณ์ | ผล |
|---|---|
| จบ 60 วัน ลูกค้าเลือกซื้อขาดภายใน 30 วัน | หักค่า pilot 100% · ออกไลเซนส์ + pack source code หรือย้ายไปเซิร์ฟเวอร์ลูกค้า/managed hosting · ข้อมูล pilot ยกไปใช้ต่อ |
| จบ 60 วัน ลูกค้าเลือกเช่า | ค่า pilot เป็นค่าเช่าล่วงหน้า · ข้อมูลยกไปใช้ต่อ · เริ่มสัญญาเช่า 12 เดือน (ค่าตั้งระบบตาม **[ตัดสินใจ]** ข้อ 4) |
| จบ 60 วัน ลูกค้าไม่ตัดสินใจ | **ไม่ต่ออายุอัตโนมัติเป็นสัญญาเสียเงิน** · ระบบเปิดอ่านอย่างเดียว/ส่งออกข้อมูลได้อีก ___ วัน **[ตัดสินใจ]** แล้วปิด → ส่งไฟล์ข้อมูล → ลบตามข้อ 6 · หลัง 30 วันค่า pilot ไม่หักคืน |
| ไม่ผ่านเกณฑ์เพราะ must-have ของ GO Along ไม่พร้อม | ลูกค้ายกเลิกได้ทันที คืน 50% · ส่งไฟล์ข้อมูล · ลบข้อมูล |

| GO Along ผิดสัญญาร้ายแรง (เช่น ระบบใช้ไม่ได้ต่อเนื่อง) | **[ทนาย]** |

## 12. ข้อกฎหมายทั่วไปที่ทนายต้องร่าง **[ทนาย]**

- การจำกัดความรับผิด (เพดาน = ค่า pilot ที่ได้รับ? **[ตัดสินใจ]**) และข้อยกเว้น (ความเสียหายทางอ้อม ข้อมูลที่ลูกค้าคีย์ผิด การยื่นภาษีด้วยตัวเลขจากระบบโดยไม่ตรวจ)
- ข้อความชัดเจนว่าตัวเลขภาษี/ประกันสังคมจากระบบใน pilot ต้องให้ผู้รับผิดชอบของลูกค้าตรวจก่อนยื่น
- เหตุสุดวิสัย · กฎหมายที่ใช้บังคับ (ไทย) · การระงับข้อพิพาท · การโอนสิทธิ์ · ภาษาที่ใช้ (ฉบับภาษาไทยเป็นหลัก)
- อากรแสตมป์ (ถ้าเข้าข่ายสัญญาจ้างทำของ/บริการ) · หนังสือรับรองหัก ณ ที่จ่ายจากลูกค้า (ค่าบริการ)
